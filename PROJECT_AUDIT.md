## 4. Техническое состояние

### 4.1. Стек и сборка

- Vite + React 19 + TypeScript  
- `base: '/pro-potolok/'` — корректно для GitHub Pages project site  
- Скрипт: `deploy = build && gh-pages -d dist -b gh-pages`  
- `homepage`: `https://TeasSty.github.io/pro-potolok`

### 4.2. Публикация

- Live открывается, HTML/JS/CSS/изображения грузятся.  
- **Live отстаёт от локальных незакоммиченных правок.**  
- Ветка деплоя: `gh-pages` (через пакет `gh-pages`).

### 4.3. Производительность (наблюдения)

- ~20 MB сырых JPEG в `public`; на странице грузятся не все, но крупные (`cta-private`, `proj-dining` локально ~0.8–0.9 MB) без WebP/AVIF.  
- Нет `loading="lazy"`, нет `srcset`/`sizes`.  
- Google Fonts — дополнительный сетевой RTT.  
- Нет code-splitting страниц (одна точка входа — нормально для лендинга).  
- SVG-схема лёгкая; фото — основной вес.  
- Дубли файлов увеличивают размер репозитория и риск рассинхрона.

## 7. Ограничения для нового дизайна

1. **Не выдумывать** цифры, отзывы, названия проектов, адреса, характеристики.  
2. **Фотобанк ограничен:** мало законченных «комнатных» интерьеров высокого разрешения; много деталей санузлов и одного/двух жилых объектов со сводом.  
3. **Не плодить фейковые проекты** из разных ракурсов одного помещения.  
4. **VK-кадры с оверлеем текста** нельзя честно класть крупно без перекропа/исходников.  
5. **Юридически/маркетингово:** согласия клиентов на публикацию — неизвестны.  
6. **Деплой:** учитывать `base: /pro-potolok/` или смену на custom domain.  
7. **Нет backend:** заявки = телефон / VK / будущая форма (нужен сервис).  
8. **Live и local расходятся** — любой релиз должен явно включать commit + `npm run deploy`.  
9. **Мобильный приоритет:** без меню текущий сайт на телефоне полуслепой.  
10. **Производительность:** нужен пайплайн оптимизации изображений (WebP, размеры, lazy).

## 9. Итог аудита

Сайт — компактный Vite/React лендинг с рабочим GH Pages, сильным по атмосфере Hero и ограниченным, но ценным фотоархивом реальных монтажей. Главные риски перед переосмыслением: **непроверенные цифры**, **дырявый интерактив**, **дубли и коллажи в медиа**, **отсутствие мобильной навигации и форм**, **рассинхрон local/live**.  

Текущий визуальный дизайн и незакоммиченные итерации **не рекомендуются как основа** нового сайта — только факты, контакты (после сверки) и отобранные исходные фото.
